# Игровое выполнение практических работ

## Привязки восьми механик - 2026-09-29

По MINIGAME-MAPPING-D-001 новые версии карточек связывают действие и игровое
поле по смыслу. Изменённые определения добавляются с новыми ID; старые
определения и сохранённые карточки остаются доступными. Начатые партии и
старые предложения не переключаются на другую механику при обновлении.
Связь поколений сохраняет историю семейства, cooldown и зачёт сюжетного
завершения. Расходы, награды, предметы и сюжетные факты прежние.

| Оплачиваемое дело | Механика будущих выдач |
| --- | --- |
| Настроить малый телескоп | Точность |
| Линзы любят чистоту | Точность |
| Посылки по причалам | Найти отличия при сверке посылок |
| Канаты запутались | Соединить канаты |
| Успеть до дождя | Точность |
| Груз до отплытия | Укладка ящиков |
| Крепкий узел | Соединить канаты |
| Порядок на витрине | Найти отличия на полках |
| Заказы на подносе | Точность |
| Весы любят точность | Точность |
| Ни одного забытого заказа | Найти пары |
| Знак под слоем пыли | Найти пары |
| Смотритель просит помочь | Сравнение цен с явным контекстом сверки стоимости |

Контекст `EventGameMedia` используется также для оплачиваемых дел; заголовок
берётся из текущего `EventPresentation`. Инструкция управления всегда следует
фактическому `DeedGameKind`. Поиск пар использует исходные восемь `deed_pair_*`
иллюстраций во всех контекстах. Дополнительные входы в сигналы и фонари
находятся в сюжетных работах ниже: тестер - последовательность сигналов;
реле - погасить контрольные лампы перед запуском.

## Описание контента - 2026-09-27

По ARCH-D-003 механика задаётся рядом с вариантом в `EventChoiceSpec.gameKind`
(для сюжетного авторского формата - в `LoreScene` / `LoreOption`), затем
компилируется в `EventPolicy.choiceGameKinds`. Отдельный проход каталога
`withStoryActionGames` удалён. Инструкция и иллюстрации находятся в
`EventPresentation.media.game`; они не назначают механику или награду.
Текущие привязки, исторические ID и последствия сохранены. См.
[единые правила описания событий](event-authoring.md).

## Лоровая очистка - 2026-09-27

ADVENTURE-D-015 уточняет только G1.03 «Пластина с тем же знаком»:
оба варианта выполняются напрямую, без мини-игры. Состав стоит 3 монеты
и не тратит силы; ручная работа расходует прежнюю `SMALL_WORK = 1` без денег.
«Вернуться позже» - пауза без списания. Обе завершённые ветви дают прежние
факты `plate_found`/`plate_symbol`. Отдельная неожиданная трата с повторным
налётом по ADVENTURE-D-012 сохраняет мини-игру.

`campaign-choice-v2:G1.03` добавляется отдельным immutable определением;
старый v1 и его единственный ответ остаются для истории. В главе новый ID
заменяет старый, а двусторонние completionAliases засчитывают оба поколения
ответов и сохраняют условия следующего G1.04. Нерешённые экземпляры переходят
на новый ID через тот же `eventReplacements`, уже выполненные не меняются.
Прошлая v1-привязка игры остаётся исторической; актуальный узел не содержит
`choiceGameKinds`. При нехватке монет или сил соответствующая ветка недоступна.

## Очистка налёта - 2026-09-27

ADVENTURE-D-012 добавляет `figma-2326-160-v3`: очистка составом за 3 монеты
или ручная очистка через PRECISION за 2 силы. «Средне устанет» уже есть в
исходном снимке Figma; сопоставление двум силам использует D-050. Исходная
кнопка «Отложить расшифровку» не означала ручной очистки: этот вариант теперь
явно подтверждён пользователем. Откладывание на завтра остаётся отдельным.
Начало игры не списывает ресурсы; завершение защищено текущей ревизией и
статусом события. Обе успешные ветви снимают блокировку сюжета.

V2 сохраняется целиком для существующих решений. V3 добавляется append-only,
только она предлагается заново; её cooldown учитывает прежние предъявления
v2. `GameCatalog.eventReplacements` объявляет v2 → v3; подготовка сессии и
восстановление заменяют только ссылки нерешённых SCHEDULE occurrences через
агрегатный `update`, читая последнее состояние в транзакции. ID, порядок,
статусы, журнал, старые решения и предъявления сохраняются. RESULT/COMPLETED
и экземпляры с записанным решением не меняются. Revision повышается один раз
при фактической замене; повтор не создаёт новых последствий.

Room остаётся v20, snapshot - format 4. История технического согласования
добавляется отдельно от игровых решений. Новый fingerprint каталога не
разрешает пересчитывать старую историю по новым определениям; новые оплаты
v3 можно сравнить с ручной работой через существующую учебную гипотезу
«если закончить работу».

Обновлено 2026-09-26. Исправление по просьбе пользователя: новые практические
действия истории не должны завершаться одной кнопкой с сообщением о готовой работе.
Привязка ниже - реализация этого требования с существующими механиками, а не
дословное требование исходных Figma-карточек. Диалоги, чтение и поездки сохраняют
свои прежние действия. Денежные суммы, силы, сюжетные факты и порядок глав не меняются.

| Сюжетное действие | Игровая механика |
| --- | --- |
| G1.03 очистить пластину | Напрямую за деньги или силы, без мини-игры (ADVENTURE-D-015) |
| N1.WHEEL закрепить колесо | Точность |
| G2.03 `repair`, укрепить мост | Соединить канаты креплений; `detour` остаётся отдельным обходом |
| N3.ACCESS разобрать находки перед отсеком | Пары приборов |
| N3.WORKBENCH открыть технический отсек | Точность |
| G3.06 разобрать старую полку | Найти отличия |
| G3.08 проверить крепления | Точность |
| G3.09 достать ящик | Уложить мешающие ящики ровной стопкой |
| G3.10 разобрать технический архив | Пары карт и записей |
| G3.11 проверить тестер | Повторить последовательность сигналов |
| G4.02 разложить карты с Луной | Пары карт и записей |

| G5.08 восстановить реле с Тико | Погасить контрольные лампы перед запуском |

Таким же допуском закрыты 13 ручных альтернатив неожиданных RANDOM-событий:
зашить лямку; восстановить карту; очистить рюкзак; починить штатив; очистить
фонарь; укрепить верстак; перенести линии карты; очистить компас; переписать
свиток; сшить журнал; очистить рычаг; подогнать ящик; заколотить окно.
Прежняя версия карточки со смолой также защищена, если осталась в сохранении.
Копирование карт и записей использует пары. В новых версиях переплёт журнала
восстанавливается соединением нитей (PIPES), крышка ящика подгоняется через
точность. Прежние MEMORY-версии журнала и ящика сохранены для старых карточек.
Остальные перечисленные ручные работы используют точность.
Инструкция управления строится по тому же типу механики, что игровое поле.
Оплата помощи, выбор другого телескопа, обход и перенос рабочего
места сохраняют прежние действия.

`EventPolicy.choiceGameKinds` связывает конкретную ветку STORY/RANDOM с механикой.
`StartStoryGame` проверяет актуальное событие, ветку, сюжетные условия, еду,
силы и доступность цены. Открытие поля не применяет последствия выбора.
`CompleteStoryGame` повторно проверяет эти условия и тип завершённого результата,
затем атомарно записывает прежние последствия и закрывает событие. Прямые
`Choose`/`CompleteEvent` для игровой ветки отклоняются. Выплата по точности
продолжает действовать только для оплачиваемых EARNING-поручений; у STORY она
не появляется и не пересчитывается; то же относится к ручным RANDOM-работам.
Технические имена команд сохранены для совместимости, хотя их контракт теперь
охватывает оба типа событий. Все 13 EARNING-поручений и их прежние
версии сохраняют собственные привязки к мини-играм.

Кнопка «Назад» сохраняет паузу без выполнения действия, расхода сил и выплаты.
Повторное открытие создаёт новую партию по существующему правилу выхода из
мини-игры. Маршрут `deed_game` содержит occurrenceId и необязательный choiceId;
старые маршруты без choiceId по-прежнему открывают EARNING. Восстановление
завершённого или приостановленного маршрута не выполняет действие повторно.
В мини-игре показаны её место, предмет/персонаж и инструкция для работы;
карты памяти используют общий исходный набор по MINIGAME-UI-D-001.
Иллюстрации не выдают предметы.

Новые команды сериализуются в существующей истории; новые таблицы/поля Room не
нужны. Журнал дня и аналитическая проекция учитывают только завершение.
Текущая версия переходов fingerprint - 13 (SCHEDULER-D-002): старые записи остаются читаемыми,
а несовместимый исторический replay не маскируется под точное сравнение.
В Хроноскопе нельзя подставлять старый результат мини-игры в другую практическую
ветку. Для ручной работы с фиксированными последствиями доступна явная гипотеза
«если закончить работу»: чистый `simulateCompletedWork` считает прежнюю цену и
силы без выдуманного score. Этот API изолирован от `dispatch`, не записывает
игру и не создаёт факты реального заработка. Платная помощь и ручная работа
по-прежнему сравниваются в обе стороны, а награда EARNING не симулируется так.

Контекст финансового выбора переносится в завершение только из совпадающей
сохранённой команды начала игры, если её `after` полностью совпадает с текущим
состоянием. Пауза, новая ревизия, еда, бюджет или перевод монет не позволяют
приписать старый показ новой ситуации. Выбранное срочное дело для сравнения
деньги/силы переносится из того же проверенного источника. Само открытие поля
не создаёт факт завершённого выбора ресурсов.
