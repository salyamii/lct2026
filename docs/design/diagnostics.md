# Локальный журнал сбоев — 2026-09-29

По DIAGNOSTICS-D-001 из [реестра решений](decisions.md) приложение сохраняет
технический отчёт о необработанном JVM-исключении в своём локальном хранилище.
Журнал не отправляется на бэкенд и не использует стороннюю аналитику.
В настройках кнопка «Скачать журнал» открывает системный выбор файла `.txt`;
пользователь выбирает, куда его записать. Дополнительные разрешения на файлы
не запрашиваются, а отправка отчёта другому человеку остаётся отдельным действием.

`FileCrashJournal` хранит не более четырёх отчётов, каждый не больше 64 × 1024
символов. Они переживают пересоздание объекта и следующий запуск приложения.
Каталог `noBackupFilesDir/diagnostics` исключён из системного резервного копирования;
удаление приложения или его данных удаляет и локальные отчёты. Экспорт не удаляет их.
При экспорте ограничиваются и старые файлы, созданные до введения лимита.
Сначала записываются минимальные сведения; подробности исключения ограничены
по объёму и глубине. Длинные цепочки причин, циклы и suppressed-исключения
не должны приводить к бесконечному обходу. Журнал не ждёт Room или корутин.

Контекст содержит только технические признаки состояния приложения: версию,
фиксированный тип экрана, главу, возраст и подобные диагностические значения. Снимки мира,
полный игровой журнал, имена питомцев, device/profile ID и секреты в контекст
не добавляются. Отчёт также содержит тип/сообщение исключения и доступный стек.

`ReportingExceptionHandler` сохраняет исходное исключение и передаёт тот же
объект прежнему обработчику. Ошибка записи не подменяет его; завершение процесса
вызывается и при ошибке прежнего обработчика. Повторный или вложенный вход
не запускает запись отчёта второй раз.

На Android 11 / API 30 и выше экспорт дополнительно включает доступную системную
сводку последних шести завершений и до двух текстовых ANR-трасс по 32 К символов,
если ОС предоставляет эти данные. Двоичные native tombstone в текст не копируются. Нативный
сбой, нехватка памяти, принудительная остановка или уничтожение процесса могут
не оставить JVM-стек; наличие полного отчёта для них не гарантируется.
Само добавление диагностики не доказывает причину ранее сообщённого вылета.
Системные сведения предоставляет [ApplicationExitInfo](https://developer.android.com/reference/android/app/ApplicationExitInfo);
они могут отсутствовать или быть вытеснены из ограниченной истории Android.

Исходники JVM-проверок: [FileCrashJournalTest](../../app/src/test/java/ru/nksk/lctapp/data/diagnostics/FileCrashJournalTest.kt)
и [ReportingExceptionHandlerTest](../../app/src/test/java/ru/nksk/lctapp/data/diagnostics/ReportingExceptionHandlerTest.kt).
Android API в этих тестах не используются; приложение и
эмулятор для этой работы не запускаются.
