# Финансовый цикл: реализация 2026-09-24

Основание: FINANCE-D-001–FINANCE-D-009 и BALANCE-D-001–BALANCE-D-003
в [реестре решений](decisions.md).
Рабочая база — `main` `51a4387`, схема Room 16 → 17 → 18. Это описание локального
кода; серверный API и родительский интерфейс не объявляются реализованными.

## Что сохраняет движок

- Два реальных остатка: доступные деньги и накопления. План «Нужно / Хочу /
  Коплю / Запас» выражает намерение, черновик не меняет остатки. Переводы явные;
  снятие требует подтверждения. Части большой цели оплачиваются накоплениями.
- Финансовые периоды связаны с выбранными проектами. Выбор нового проекта
  открывает его план без изменения денег. Все подтверждённые редакции плана,
  их основания и фактические операции сохраняются.
- Перед финалом новой главы нужны местные учебные этапы: обеспечить питание,
  практиковать регулярные накопления и разобрать план с фактом по категориям.
  Учитываются сохранённые пополнения после разных поступлений и соблюдение
  плана либо его объяснённый разбор с реалистичной корректировкой. Если реального
  окна наблюдения недостаточно, отдельная практика позволяет продолжить игру,
  не приписывая ребёнку наблюдаемую регулярность. Эти действия не являются порогом
  освоения финансовых навыков для родителя. Импортированная незавершённая глава
  не получает выдуманную историю и не блокируется задним числом.
- Принятая команда сохраняет снимок, точные денежные операции, факты и outbox
  одной транзакцией. Повтор того же запроса не дублирует результат. Отклонённые
  команды сохраняются как попытки без денежных операций. Превью не пишет журнал.

Миграция сохраняет все реальные деньги v16: `available = needs + wants +
reserve + unallocated`, `savings = прежнее savings`. Старый план и текущий
черновик сохраняются с явной границей начала новой истории. См.
[схему](schema-normalization.md) и [требования хранения](room-persistence.md).

## Источники всех 12 навыков

| Навык | Подключённый источник | Ограничение вывода |
| --- | --- | --- |
| FIN-01: сравнение сумм | Реальные вопросы мини-игры в деле: показанные суммы, сторона ответа, серия, попытка | Тренировка отдельно; награда и скорость не оценивают навык |
| FIN-02: планирование | Подтверждённые версии бюджета, показанные нужды, причина редакции | Исходная нехватка денег и неизвестная причина не превращаются в ошибку |
| FIN-03: нужды перед желаниями | Покупка или отказ от WANT с остатками и стоимостью известной еды | Недоступная покупка не даёт самостоятельного успеха |
| FIN-04: до следующего дохода | Полная последовательность семи дней между недельными поступлениями | Частичная импортированная неделя неполна; бесплатная еда сама по себе не ошибка и не доказательство покрытия расходов |
| FIN-05: накопление | Явные переводы, снятия, покупки частей, завершённый цикл цели | Круговой перевод не даёт прогресса; один перевод нельзя раздробить на независимые навыки |
| FIN-06: отложенное желание | «Хочу позже — сначала цель» и последующее применение денег к этому приоритету | Обычный отказ не приписывает желание или мотив |
| FIN-07: запас | Подтверждённое намерение оставить запас, конкретная неожиданная трата и завершённое окно наблюдения | Учитывается запас до первого показа счёта; остаток без намерения или неизвестный момент показа не даёт положительного вывода |
| FIN-08: адаптация | Неожиданная трата + явно выбранная связь с новым планом | Само несчастливое событие не является ошибкой ребёнка |
| FIN-09: деньги, силы, время | Доступные варианты оплатить/сделать самому; явно выбранное дело со сроком сегодня | Без названного приоритета нет искусственно правильного выбора; проверяется реальная возможность выполнить дело после каждого варианта |
| FIN-10: заработок | Явное «Заработать на цель», дело, фактическая награда, последующее финансовое действие | Максимум награды не выдается за доход; точность игры не оценивает финансовое планирование |
| FIN-11: последствия | Вопрос о причине + следующее сопоставимое реальное решение | Верный ответ без следующей ситуации не объявляется применением |
| FIN-12: доходы и расходы | Ответ по реальным операциям периода или проверенному пересчёту | Просмотр суммы не считается ответом; перевод не считается расходом |

`AnalyticsFact → HistoryLearningProjection → SkillEvaluator → SkillProfile`.
Профиль содержит основания, неполные и нейтральные эпизоды, успешные/трудные
наблюдения, помощь и контексты. Нормы возраста и численные пороги «освоил» ещё
не согласованы. Их нельзя подменять произвольным процентом в интерфейсе.

## Идентификаторы навыков API

По ANALYTICS-API-D-001 от 2026-09-26 доменный `SkillId` совпадает с backend
`StrEnum`, переданным пользователем. Значение enum сериализуется строкой FIN-кода,
например `"FIN-05"`; внутреннее имя Kotlin в обмен не уходит.

| Имя | Значение |
| --- | --- |
| `COMPARE_AMOUNTS` | `FIN-01` |
| `PLAN_BUDGET` | `FIN-02` |
| `PRIORITIZE_NEEDS` | `FIN-03` |
| `MAKE_MONEY_LAST` | `FIN-04` |
| `SAVE_FOR_GOAL` | `FIN-05` |
| `DELAY_PURCHASE` | `FIN-06` |
| `BUILD_EMERGENCY_FUND` | `FIN-07` |
| `ADAPT_AFTER_EXPENSE` | `FIN-08` |
| `COMPARE_COSTS` | `FIN-09` |
| `PLAN_EXTRA_INCOME` | `FIN-10` |
| `RECONSIDER_DECISION` | `FIN-11` |
| `UNDERSTAND_INCOME_AND_EXPENSES` | `FIN-12` |

`SkillObservation` и `SkillProfile` используют один общий тип. Согласование имён
не меняет выводы оценщика: FIN-09 сохраняет сравнение затрат ресурсов, FIN-11 —
объяснение последствий и применение вывода. Идентификатор навыка сам по себе не
свидетельствует об освоении. Сохранённые факты и подписанные снимки остаются
прежнего формата; enum не добавляется задним числом в журнал.

HTTP-клиент и доставка на сервер ещё не подключены. Этот enum фиксирует тип
идентификатора для согласуемого API, но не задаёт отсутствующие URL, поля пакета
или способ серверной агрегации.

## Машина времени

Доступ открывается существующим сюжетным фактом `chronoscope_unlocked`.
Сохраняются исходный запрос, состояния до/после и отпечаток каталога. Пересчёт
сначала проверяет воспроизводимость настоящего результата, затем меняет одно
решение и повторяет последующие записанные действия до выбранной границы.
Если дальнейшее действие невозможно, результат явно останавливается на общем
достоверном участке. Новые заработки и решения за ребёнка не придумываются.
Отпечаток включает `GameCatalogFingerprint.TRANSITION_VERSION`: при изменении
семантики переходов эту версию нужно повышать даже без изменения каталога.

С 2026-09-27 версия переходов 11 учитывает BALANCE-D-003: при положительном
максимуме завершённого оплачиваемого дела выплата равна
`max(1, floor(максимум × верные попытки / все попытки))`. Нулевые сюжетные
награды и незавершённые дела не получают монету; прошлые выплаты сохраняются.
Несовместимый исторический отпечаток не позволяет пересчитать прежний результат
по новой формуле. Формат snapshot и схема Room этим правилом не меняются.

Исторический разбор плана воспроизводится с исходной историей до вопроса.
Альтернативная ветка останавливается перед новым разбором плана: после изменения
трат требуется новый вопрос и ответ, их нельзя заимствовать из настоящей ветки.

Базовый UI сравнивает до конца сохранённой части выбранного дня. В расчёте
раздельно учитываются доходы, расходы, пополнения, снятия, остатки и состояние
прохождения. Настоящая игра не меняется. Вопрос с объяснением — реальное учебное
действие с `learningContext=COUNTERFACTUAL`; деньги альтернативной ветки не
попадают в наблюдения настоящего финансового поведения.

## Интерфейс и передача серверу

Вход «История и практика» есть в блоке монет главной и в бюджете. Раздел
показывает текущие остатки, исходный/последний план периода, реальные операции,
практику и хроноскоп. Это рабочая базовая компоновка для последующей отрисовки.
Карточка финала направляет в практику, когда местного опыта не хватает.
[Дизайнерский бриф](requirements/designer-handoff-2026-09-24.md) содержит варианты.

Для будущего сервера доступны `pendingOutbox/acknowledgeOutbox`,
`exportSnapshot/restoreSnapshot`, версия формата и checksum. Restore проверяет
цепочку истории, оба счета и ожидаемую локальную ревизию/sequence, не сливает
две игры автоматически. REST-клиент, WorkManager, код связи устройств,
родительские домашние задания и выдача подарков ждут реального API и дизайна.

Повседневный каталог расширен до 25 неожиданных ситуаций и 8 предложений покупок;
30 исходных карточек выгружены из Figma. История показа, интервалы повторов,
предметные и сюжетные условия, новые награды и переход «купил → открыл → надел»
описаны в [дополнении по балансу](requirements/everyday-balance-2026-09-24.md).
Room 18 сохраняет историю показов и сведения о финансовых этапах. Миграции
сохраняют существующие деньги и прохождение. Формат экспорта 2 поддерживает
чтение прежнего формата 1 без подмены его исходной подписи.

История читается отдельно от основной подписки, пересчёт машины времени
выполняется вне UI-потока. Приложение, эмулятор и тесты в этой доработке не
запускаются по предпочтению пользователя; проверяются сборки и компиляция
тестовых исходников. Проверка выполнения сценариев на устройстве остаётся
за пользователем, исходники регрессионных проверок добавлены.

Проверка итогового кода 2026-09-24: `:core:game:compileTestKotlin`,
`:app:compileDebugUnitTestKotlin`, `:app:compileDebugAndroidTestKotlin`,
`:app:assembleDebug`, `:app:lintDebug` — **BUILD SUCCESSFUL**.
Lint: 0 ошибок, предупреждения сохранены в отчёте сборки. `git diff --check`
и локальные ссылки новых документов проверены. Это компиляция тестовых
исходников, не утверждение об успешном выполнении тестов.


### Скрытие повторной сводки — 2026-09-27

По ADVENTURE-D-006 бесплатные лоровые карточки и предложения покупок не
показывают повторный полный баланс/потребность в еде. Факт покупки и реальные
суммы по-прежнему записываются, но `informationPresented`/полный показанный
финансовый контекст не выставляется за скрытые данные. При текущем критерии
FIN-03 такая WANT-карточка сама по себе даёт недостаточно свидетельств; оценка
не повышается за факт, которого игрок не видел. Остальные доказательства навыка
из бюджета и питания сохраняются. Кнопка обычного отказа не создаёт явного
намерения FIN-06 отложить покупку ради цели.
