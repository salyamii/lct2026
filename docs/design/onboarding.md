# Первый экран onboarding

## Утверждено пользователем, 2026-09-19

Отдельный Gradle-модуль `:feature:onboarding` показывает выбор персонажа новым
игрокам. Существующее сохранение пропускает экран. Изначально никто не выбран,
«Начать приключение» визуально неактивна, но нажатие открывает диалог
«Чтобы начать приключение, выбери персонажа нажав на него». Нажатие на лисёнка выделяет его; только кнопка
переходит к кастомизации (CUST-D-004 от 2026-09-20). Сова и аксолотль серые, их нажатие показывает
анимированную подсказку из Figma и не выбирает их. Игровые модели, сюжеты и
разблокировки этих двух персонажей не добавляются. Значок информации убран.

[Макет](https://www.figma.com/design/bAod1cKtTX9Q8omQ067q3q/?node-id=2186-693).
Текст подсказки: «Персонаж пока недоступен\nОткроется во время приключения».
Вторая строка — текст дизайна, не реализуемая механика разблокировки.

## Технический подход

Модуль владеет экранами выбора и кастомизации. `app` передаёт ресурсы и шрифты;
AppStartupViewModel читает GameSession и управляет шагами Choose/Customize/Accessories/GoalSelection/Introduction/Ready.
Начало приключения сохраняет отдельный черновик и открывает кастомизацию,
не создавая игрового снимка. Редактирование сохраняет черновик последовательно;
холодный запуск без игры восстанавливает его. UI и системный Back из Customize очищают черновик
и возвращают выбор персонажа, следующая кастомизация начинается с defaults.

«Продолжить» открывает аксессуары, «Применить» — выбор цели (CUST-D-019).
«Выбрать цель» открывает Introduction. Только «В путь!»
сохраняет имя (непустое, без крайних пробелов), характер, цвет, возраст CUB и
выбранный аксессуар и selectedGoalId вместе с начальным снимком через атомарный initialize-if-absent.
Room в той же транзакции удаляет черновик. Сам переход не запускает день,
событие или награду. Характер сохраняется без придуманных эффектов.
Повторные нажатия блокируются во время записи; существующая игра не перезаписывается.
Ошибка чтения не означает новую игру; ошибка записи оставляет экран для повтора.

Наличие полного сохранения — признак завершения onboarding; отдельного флага нет.
После commit LctNavHost открывается с MainMenu в корне, Back не возвращает onboarding.
Room v13 добавляет характер и черновик к main-v12; прежние сохранения пропускают сценарий. Малыш отображается в Preview, кастомизации и меню в выбранном окрасе.
Источники: [малыш](https://www.figma.com/design/bAod1cKtTX9Q8omQ067q3q/?node-id=87-21),
[кастомизация](customization-preview.md), [схема](schema-normalization.md).

Нажатия проверяются по альфа-каналу персонажей в координатах отрисовки, от
переднего слоя к заднему. Свечение не расширяет область нажатия. Для TalkBack
и клавиатуры каждый персонаж имеет отдельное именованное действие. Светлый
контур и мягкое свечение плавно появляются у выбранного лисёнка.

Портретный экран прокручивается при нехватке высоты/увеличении шрифта; широкий
экран использует две колонки. Системные панели учитываются через safeDrawing.
Шрифты и совпадающее artwork переиспользуются, недостающие экспорты хранятся
в `app/src/main/res/drawable-nodpi` как lossless exact WebP с полным холстом.

Проверка по текущему указанию пользователя: сборка приложения и компиляция
регрессионных тестов, без запуска приложения, эмуляторов или тестов.

По CUST-D-016 после образа открывается Accessories. Подтверждение доступного
аксессуара открывает GoalSelection по CUST-D-019. Room v15 сохраняет цель, этап и
примеряемый предмет в черновике. Back с аксессуаров возвращает к образу.

CUST-D-019: после аксессуаров выбирается одна из трёх стартовых целей. Без выбора
подтвердить нельзя. Introduction называет выбранное приключение без денежных
сообщений. Только «В путь!» создаёт игру. Back из Introduction возвращает
GoalSelection, затем Accessories. Возврат к образу сохраняет цель; возврат
к персонажам очищает весь черновик.

Room v15 добавляет nullable ONBOARDING_DRAFT.goal_id. Старый INTRODUCTION
мигрирует в GOAL_SELECTION без назначения цели. Существующие игры не меняются.
GameSession проверяет доступность по начальному снимку. Игра, выбранная цель
и удаление черновика фиксируются одной транзакцией. День и событие начинаются
только по последующему «Продолжить день» из меню.

AdventureGoalSelectionScreen и AdventureStartedScreen находятся в :feature:onboarding,
получают данные и callbacks. Ресурсы связывает app, AppStartupViewModel владеет
StateFlow и сохранением. Preview используют те же реальные ID, подписи и ресурсы.
