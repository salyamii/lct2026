# Первый экран onboarding

## Утверждено пользователем, 2026-09-19

Отдельный Gradle-модуль `:feature:onboarding` показывает выбор персонажа новым
игрокам. Существующее сохранение пропускает экран. Изначально никто не выбран,
«Начать приключение» визуально неактивна, но нажатие открывает диалог
«Чтобы начать приключение, выбери персонажа нажав на него». Нажатие на лисёнка выделяет его; только кнопка
открывает вступительный ролик, затем кастомизацию (MEDIA-D-002 от 2026-09-27,
уточнение CUST-D-004). Сова и аксолотль серые, их нажатие показывает
анимированную подсказку из Figma и не выбирает их. Игровые модели, сюжеты и
разблокировки этих двух персонажей не добавляются. Значок информации убран.

[Макет](https://www.figma.com/design/bAod1cKtTX9Q8omQ067q3q/?node-id=2186-693).
Текст подсказки: «Персонаж пока недоступен\nОткроется во время приключения».
Вторая строка - текст дизайна, не реализуемая механика разблокировки.

## Технический подход

Модуль владеет экранами выбора и кастомизации. `app` передаёт ресурсы и шрифты;
AppStartupViewModel читает GameSession и управляет шагами
Choose → IntroVideo → Customize → Accessories → GoalBriefing → GoalSelection → Introduction → Ready.
«Начать приключение» сначала сохраняет отдельный черновик `OnboardingStep.Profile`,
затем открывает временный IntroVideo, не создавая игрового снимка. Завершение ролика,
«Пропустить» и системный Back открывают Customize с тем же черновиком.
Позиция ролика живёт только в AppStartupViewModel: смена конфигурации её сохраняет,
холодный запуск восстанавливает Profile сразу в Customize. Сам ролик и выход из
него не пишут Room, не вводят новый сохраняемый шаг и не вызывают игровой переход. Редактирование сохраняет черновик последовательно;
холодный запуск без игры восстанавливает его. UI и системный Back из Customize очищают черновик
и возвращают выбор персонажа, следующая кастомизация начинается с defaults.

«Продолжить» открывает аксессуары, «Применить» - вступление GoalBriefing
(CUST-D-020), «Дальше» - выбор цели (CUST-D-019).
«Выбрать цель» открывает Introduction. Только «Дальше» на объяснении бюджета
сохраняет имя (непустое, без крайних пробелов), характер, цвет, возраст CUB и
выбранный аксессуар и selectedGoalId вместе с начальным снимком через атомарный initialize-if-absent.
Room в той же транзакции удаляет черновик. Сам переход не запускает день,
событие или награду. Характер сохраняется без придуманных эффектов.
Повторные нажатия блокируются во время записи; существующая игра не перезаписывается.
Ошибка чтения не означает новую игру; ошибка записи оставляет экран для повтора.

Наличие полного сохранения - признак завершения onboarding; отдельного флага нет.
После commit LctNavHost открывается с MainMenu в корне, Back не возвращает onboarding.
Room v13 добавляет характер и черновик к main-v12; прежние сохранения пропускают сценарий. Малыш отображается в Preview, кастомизации и меню в выбранном окрасе.
Источники: [малыш](https://www.figma.com/design/bAod1cKtTX9Q8omQ067q3q/?node-id=87-21),
[кастомизация](customization-preview.md), [схема](schema-normalization.md).

Нажатия проверяются по альфа-каналу персонажей в координатах отрисовки, от
переднего слоя к заднему. Свечение не расширяет область нажатия. Для TalkBack
и клавиатуры каждый персонаж имеет отдельное именованное действие. Светлый
контур и мягкое свечение плавно появляются у выбранного лисёнка.

Портретный экран прокручивается при нехватке высоты/увеличении шрифта; широкий
экран использует две колонки. Системные панели учитываются через safeDrawing.
Шрифты и совпадающее artwork переиспользуются, недостающие экспорты хранятся
в `app/src/main/res/drawable-nodpi` как lossless exact WebP с полным холстом.

Проверка по текущему указанию пользователя: сборка приложения и компиляция
регрессионных тестов, без запуска приложения, эмуляторов или тестов.

По CUST-D-016 после образа открывается Accessories. Подтверждение доступного
аксессуара открывает GoalBriefing по CUST-D-020. Room v15 сохраняет цель, этап и
примеряемый предмет в черновике. Back с аксессуаров возвращает к образу.

CUST-D-019/CUST-D-020: после аксессуаров и вступления выбирается одна из трёх стартовых целей. Без выбора
подтвердить нельзя. Introduction объясняет бюджет по CUST-D-021. Только «Дальше» на объяснении бюджета создаёт игру. Back из Introduction возвращает
GoalSelection, затем GoalBriefing и Accessories. Возврат к образу сохраняет цель; возврат
к персонажам очищает весь черновик.

Room v15 добавляет nullable ONBOARDING_DRAFT.goal_id. Старый INTRODUCTION
мигрирует в GOAL_SELECTION без назначения цели. Существующие игры не меняются.
GameSession проверяет доступность по начальному снимку. Игра, выбранная цель
и удаление черновика фиксируются одной транзакцией. День и событие начинаются
только по последующему «Продолжить день» из меню.

AdventureGoalBriefingScreen, AdventureGoalSelectionScreen и BudgetIntroductionScreen находятся в :feature:onboarding,
получают данные и callbacks. Ресурсы связывает app, AppStartupViewModel владеет
StateFlow и сохранением. Preview используют те же реальные ID, подписи и ресурсы.

## Видео после выбора персонажа - 2026-09-27

По MEDIA-D-002 [в реестре](decisions.md) вступление использует предоставленный
`media/video/intro_fox.mp4`. Выбор персонажа сам по себе не запускает воспроизведение:
нужна кнопка «Начать приключение» и успешное сохранение Profile-черновика.
Если запись не удалась, остаётся экран выбора с повтором; существующая игра
пропускает весь сценарий. Просмотр, пропуск и Back не создают питомца в игре,
не принимают пустое имя и не пропускают последующие шаги кастомизации.
Ошибка самого ролика показывает «Продолжить» в Customize.

По MEDIA-D-003 кнопка звука на видео и переключатель настроек используют один
сохраняемый sound preference. Он управляет также музыкой глав, озвучкой и эффектами;
это Preferences DataStore, а не данные игрового мира. Видео приостанавливается
при уходе приложения в фон. UI модуля получает player и actions через slots;
плеер, lifecycle и настройка подключаются в app. [Полный контракт](intro-video.md)
и [происхождение файла](assets/media-catalog.md).

## Вступление перед выбором цели - 2026-09-23

CUST-D-020: экран использует тот же дневной холм `location_hill_day`, общий
верх и кремовую панель, что и выбор цели. В панели крупный заголовок
«Тебя ждёт большое приключение!», затем светлый блок с текстом:

> Каждое путешествие с чего-то начинается.
>
> Перед тобой три большие цели - выбери ту, которая тебе больше нравится,
> и шаг за шагом двигайся к ней.
>
> Вперёд, исследовать неизведанный мир!

Кнопка «Дальше» закреплена снизу; текст прокручивается при нехватке высоты.
Широкое окно использует существующее расположение изображения и панели рядом.
Preview добавлены для телефона, крупного текста и альбомной ориентации.

Выбор реализации: GoalBriefing сохраняется кодом GOAL_BRIEFING в существующем
текстовом поле ONBOARDING_DRAFT.step. Схема Room v16 не меняется, миграция не нужна.
Старые GOAL_SELECTION/INTRODUCTION продолжаются с прежнего места. Back из выбора
возвращает вступление, затем аксессуары; профиль, аксессуар и выбранная цель
сохраняются. Ошибка записи оставляет текущий экран для повтора; игра создаётся
только на финальном «Дальше».

## Объяснение бюджета - 2026-09-23

По CUST-D-021 финальный Introduction после выбора цели показывает
BudgetIntroductionScreen вместо AdventureStartedScreen. Верх и кремовая панель
общие с экранами целей; фон `location_hill_day`, иллюстрации категорий
`budget_needs`, `budget_wants`, `budget_savings`, `budget_reserve` переиспользуются
без изменения ресурсов. App передаёт иллюстрации через composable-slot с
GameArtwork, feature/onboarding не импортирует feature/economy.

Текст согласован пользователем: «Большие планы начинаются с маленьких решений»;
объясняет начальные 100 и ещё 100 каждые 7 игровых дней, сохранение остатка,
категории «Нужно»/«Хочу»/«Коплю»/«Запас», недельный минимум 35 на нужное и
назначение накоплений для цели, баланс желаний и цели и изменение распределения.
По ADVENTURE-D-018 предмет цели можно оплатить из копилки и текущих денег вместе;
до покупки показываются источники списания и риск нехватки на еду.
Текст и четыре карточки прокручиваются; «Дальше» закреплена снизу. Preview
покрывают телефон, крупный шрифт, альбомную ориентацию и планшет.

Существующий этап INTRODUCTION сохраняется без изменения Room. Back возвращает
выбор цели с прежним выделением. «Дальше» атомарно создаёт игру и удаляет черновик;
при ошибке остаётся этот экран с повтором. Пока идёт запись, кнопки заблокированы.
Если закрыть приложение до завершения, Introduction восстановится. Наличие
сохранённой игры пропускает весь onboarding: объяснение не повторяется при
перезапуске или недельном начислении, дополнительный флаг не хранится.

После завершения открывается меню. INITIAL/RECEIPT больше не перенаправляет
автоматически с меню: «Продолжить день»/«Монетки» открывают поступление и
обязательное распределение. Незавершённая ALLOCATION, новые недельные поступления
и восстановленные игровые маршруты по-прежнему подчиняются бюджетному барьеру.
