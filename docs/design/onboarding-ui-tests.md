# Проверки UI онбординга

Используются существующие JUnit 4, Compose UI Test и Hilt; новых плагинов нет.
Основание — рекомендации adaptive, testing-setup и edge-to-edge: разные размеры
окна, крупный текст, восстановление состояния, семантика и реальные взаимодействия.

## Наборы

- `OnboardingAdaptiveTest`: 36 параметризованных проверок трёх экранов.
  Девять комбинаций 400/610/900 × 400/500/1000 dp, компактный телефон и
  альбомное окно со шрифтом 150%, планшет 1280 × 800. Проверяются доступность
  вариантов и кнопок, переход между вертикальной и двухколоночной раскладкой,
  отступы под status/navigation bars и боковые вырезы, минимальная высота
  основной кнопки 48 dp. Пиксельная проверка снимка ловит белую полосу в области
  navigation bar; тест не ограничивается чтением модификаторов.
- `OnboardingScreenTest`: валидация только при отправке, IME Done снимает фокус,
  входное состояние меняет текст и образ, переключение размеров сохраняет выбор,
  сцена не движется вместе с формой, восстановление через StateRestorationTester,
  свайпы и семантическое перелистывание, закрытый предмет не применяется,
  высота подсказки не меняется, сохранение блокирует действия, ошибка допускает повтор.
- `OnboardingJourneyTest`: реальные MainActivity и Hilt ViewModel с подменой
  хранилища в памяти. Проверяет диалог до выбора, недоступного героя, выбор
  клавиатурой, весь путь до меню и пересоздание Activity на каждом шаге.
  До последнего подтверждения игры нет; после него сохраняются имя, цвет и аксессуар.
  На следующем запуске onboarding пропускается. Реальное Room-хранение отдельно
  проверяет `CustomizationPersistenceTest`.

Изменения production UI ограничены стабильными testTag для фона сцены, карусели
и области подсказки. Остальные запросы используют текст, описание и семантику.

## Проверка и запуск

Сборка/компиляция без запуска устройства:

```sh
./gradlew :app:assembleDebug :app:compileDebugAndroidTestKotlin
```

Инструментальные проверки запускаются отдельно по явному запросу пользователя:

```sh
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.package=ru.nksk.lctapp.onboarding
```

DeviceConfigurationOverride моделирует размер, шрифт и insets. Это не заменяет
проверку настоящей системной клавиатуры, анимации IME, системных жестов,
контраста системных иконок и физического foldable. Golden screenshot baselines
не записаны: пиксельная проверка здесь проверяет конкретный регресс фона, а не
визуальное совпадение всего экрана. Не проверяется число рекомпозиций —
проверяется видимый результат изменения состояния.

## Исправление, выявленное прогоном

На коротких окнах `performScrollTo` доводил варианты характера/цвета под
плавающую кнопку, которая перехватывала касание. Область прокрутки профиля теперь
заканчивается выше измеренной области действия. Это сохраняет доступность
вариантов без изменения закреплённой сцены или стиля кнопки.

Для проверки относительного расположения измеряется панель редактора, а не
поле имени: в коротком окне оно может находиться вне видимой части прокрутки.
Жест карусели рассчитан на ширину одной страницы, сквозной тест ожидает
асинхронного перехода после подтверждения выбора.

Итоговый прогон 2026-09-20: Pixel_10_Pro (Android 16), **44/44 прошли**,
пропусков нет. Отчёт создаётся в `app/build/reports/androidTests/connected/debug/index.html`.

## Проверка после слияния main — 2026-09-20

По явному запросу пользователя выполнены `:core:game:test`,
`:app:testDebugUnitTest`, `:app:connectedDebugAndroidTest` и `:app:assembleRelease`.
Результат: 85 + 108 JVM-тестов и 121 инструментальный тест прошли без ошибок
и пропусков на Pixel_10_Pro, Android 16. Release собран.

Прогон выявил отсутствующий binding черновика в GoalNavigationTest, старые
ожидания заголовков/первого события, неверный фильтр идентификаторов каталога,
переставленные параметры CompletedGoalProject в debug-fixture и ошибки подготовки
проверок схем (попытка downgrade после открытия актуальным builder и несколько
игр в одноигровом репозитории). Исправлены тесты, без ослабления правил движка.

Реальный дефект UI: карта перехватывала нажатие на имя на компактном экране
с fontScale=1.5. Положение карты ограничено нижней границей HUD; существующий
тест проверяет, что нажатие на имя не вызывает действий, а кнопки доступны.
