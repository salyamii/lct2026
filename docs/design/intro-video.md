# Вступительный ролик

Актуально: 2026-09-27. Ролик передан пользователем для начала игры после выбора
персонажа. Звук можно выключить прямо во время просмотра; это общая настройка
приложения, доступная также в настройках.

## Место в первом запуске

Путь: Choose → IntroVideo → Customize → Accessories → GoalBriefing →
GoalSelection → Introduction → Ready. После выбора лисёнка кнопка начала
приключения сначала сохраняет существующий черновик Profile с пустым именем.
Только успешная запись открывает ролик. При ошибке остаётся выбор персонажа
с повтором; игра не создаётся.

Окончание ролика, «Пропустить» и системный Back ведут к одному и тому же
Customize с сохранённым черновиком. Имя по-прежнему обязательно; затем идут
аксессуар, цель, объяснение бюджета и штатное первое распределение. Ни один
callback видео не вызывает `finishOnboarding`, не запускает день и не начисляет
монеты. Повторный или запоздалый callback после ухода с видео игнорируется.

## Состояние и восстановление

`AppStartupState.IntroVideo` хранит только профиль черновика, позицию воспроизведения
и ошибку плеера. Это временное состояние AppStartupViewModel; отдельного флага
в GameState, Room, снимке мира или DataStore нет. Позиция сохраняется в живом
ViewModel при пересоздании activity и передаётся новому экземпляру плеера.
Запоздалый callback старой поверхности не уменьшает сохранённую позицию.

После остановки процесса Profile уже лежит в Room: новый запуск открывает
Customize без повторного ролика. Существующий полный save имеет прежний
приоритет и сразу проходит startup gate, поэтому обновление приложения не
показывает вступление действующим игрокам. Явный возврат к персонажам и начало
нового черновика остаются отдельным началом onboarding.

## UI и звук

По MEDIA-D-007 главная тема первой главы играет на выборе персонажа и после
ролика на всех шагах onboarding. Во время `IntroVideo` app убирает только ключ
фоновой музыки: собственная дорожка MP4 и общий выключатель звука продолжают
работать. Выход, пропуск и Back снова включают первую тему, если звук разрешён.

`IntroVideoScreen` в `:feature:onboarding` владеет компоновкой. App передаёт
общий `IntroVideoPlayer` и кнопки через composable slots; модуль не зависит от
реализации плеера или настроек. `app/IntroVideoEntry` связывает callbacks с
AppStartupViewModel и использует общий `GameActionButton`. Стабильные ключи
Navigation 3 не меняются; ролик остаётся внутри стартового gate.

По уточнению MEDIA-D-009 кадр показан целиком в исходном формате 9:16, с сохранением
пропорций (`SCALE_TO_FIT`). Весь экран за ним заполняет размытая подложка из кадра
того же ролика: на высоком телефоне она видна сверху и снизу, на широком - по бокам.
Подложка - небольшой неподвижный кадр на третьей секунде (ролик начинается с чёрного),
полученный и размытый один раз вне главного потока и очереди воспроизведения.
Размер 90 × 160 ограничивает память и стоимость обработки; программное размытие
действует и на Android 7–11. Дополнительный видеоплеер и покадровое декодирование
для фона не создаются. Безопасные отступы применяются только к кнопкам и сообщениям.

MP4 читается из `assets/media/video/intro_fox.mp4` общим lifecycle-плеером:
при уходе приложения с экрана воспроизведение приостанавливается, ресурсы
освобождаются вместе с поверхностью. Видео не создаёт игровых переходов.
До чтения настройки звука показ ожидает её загрузки; если настройку прочитать
не удалось, просмотр доступен без звука с отдельным сообщением и повтором.

Рядом с «Пропустить» находится «Выключить звук» / «Включить звук». Она изменяет
общую настройку через MediaPlaybackViewModel и device MediaPreferencesRepository;
игровой снимок не меняется. Пока настройка записывается, повторное нажатие
блокируется без исчезновения кнопки. Ошибка настроек видна рядом с «Повторить»
и не блокирует выход из ролика. Ошибка самого видео показывает «Продолжить»
и ведёт к вводу имени без дополнительного сохранения.

## Проверка

Источники регрессий AppStartupViewModel покрывают ошибку записи черновика,
невозможность обойти имя и создать игру через видео, сохранение позиции,
поздние callbacks, cold restart во время ролика и пропуск для существующего save.
Проверки не запускаются по текущему предпочтению пользователя; компиляция
исходников не означает проверки воспроизведения на устройстве.
