# Описание событий и медиа

Текущая реализация: 2026-09-27. Основание — принятые
[ARCH-D-003 и ARCH-D-004](decisions.md). Игровые правила определяет
[спецификация состояний](app-state-machine.md); этот документ описывает,
куда записывать уже согласованные правила и оформление.

## Единое описание события

`EventSpec` в `:core:game` объединяет `EventDefinition`, список `EventChoiceSpec`,
общую `EventPolicy` и `EventCardCopy`. `compile()` получает из них существующие
определения событий, вариантов, эффектов, политики и итоговые тексты.
`withEventSpecs` добавляет эти определения в каталог с сохранением порядка.
Повторная регистрация уже существующего event ID запрещена.

| Что описываем | Где задаём |
| --- | --- |
| Стабильный ID, тип, исходное название и описание | `EventDefinition` |
| Короткий ключ варианта и его текст | `EventChoiceSpec.key` / `text` |
| Изменение денег и бюджетная статья | `moneyDelta` / `budgetSection` |
| Расход сил варианта | `energyCost` |
| Практическая мини-игра | `gameKind` |
| Факты, питание, предметы, состояние героя | `facts`, `feedsPet`, `itemEffects`, `petStateAfter` |
| Итог выбранного действия для истории | `recap` |
| Общие условия и расход сил события | `EventPolicy` |
| Макет карточки, актуальные подписи и медиа | `EventCardCopy.presentation` |

Полный ID варианта строится как `eventId:key`. Идентификаторы предметных эффектов
задаются явно. Нельзя переименовывать установленные ID или менять порядок ради
косметики: на них ссылаются сохранения и журнал. У расхода сил `null` означает
наследование общего расхода, а `0` — явный бесплатный по силам вариант. Для фактов
сохраняется различие между отсутствующим значением и явно пустым набором.

Правила отдельных вариантов не нужно одновременно заполнять в картах
`choiceEnergyCosts`, `choiceGameKinds`, `factsByChoiceId` и `summaryByChoiceId`:
компилятор собирает их из вариантов и проверяет отсутствие второго источника.
Общие политики по-прежнему проверяются движком на актуальном состоянии внутри
транзакции. Описание события само по себе не выполняет покупку или награду.

Сюжетные `LoreScene` / `LoreOption` и описания повседневных событий — удобные
авторские формы над тем же `EventSpec`. Мини-игра и итоговая фраза теперь задаются
рядом с вариантом; отдельного прохода `withStoryActionGames` нет. Для питания
используется `MealPolicy`, без собственного поиска «первой еды» на каждом экране.

## Оформление и ресурсы

`EventPresentation.layout` явно выбирает сцену, покупку или вступление. Наличие
иллюстрации не определяет тип карточки. `title`, `body`, `locationTitle`,
`actionLabels` и `outcomeLabels` задают текущий текст; без переопределения
используется исходный текст события. Подписи вариантов используют полные choice ID.

Типовые покупки выбирают `PurchasePresentation`, сюжетные сцены — при необходимости
`StoryPresentation`. Preset указывается в самом описании контента. Общие чтения
`presentationFor`, `displayTitle`, `displayAction` и `displayOutcome` доступны
карточке, истории и сравнению путей. Не добавляем новый список event ID в каждом
потребителе, чтобы узнать тип карточки или её заголовок.

`EventMedia` содержит смысловые ключи иллюстрации, фона и персонажа. Android-адаптер
`EventMediaArtwork` сопоставляет ключи с существующими drawable. Доменные классы
не импортируют `R`, Android или Compose. Старое сопоставление по ID в
`EventSceneArtwork` остаётся явно выделенным адаптером совместимости для прежних
сцен; новые медиа задаются через смысловые ключи.

Оформление мини-игры описывает `EventGameMedia`: инструкция, изображения пар или
предмет. Оно не выбирает игровую механику и не выдаёт предметы. Механику определяет
`EventChoiceSpec.gameKind`. При объединении оформления сцены и мини-игры сохраняем
остальные поля `media`, а для варианта без мини-игры не наследуем её оформление.

Перед добавлением изображения нужно прочитать [правила ресурсов](assets/README.md)
и проверить [каталог](assets/catalog.md). Сохраняются размеры холста, прозрачные
поля персонажей и координаты одежды. Отсутствующее изображение не подменяется
другим событием и не отключает действие.

## Музыка и озвучка

В `EventMedia` предусмотрены `musicCueKey`, `ambientCueKey`, `narrationCueKey`
и `actionAudio` с ключами звука/голоса для действия. Сейчас аудиоресурсы и
проигрыватель не подключены; пустой ключ означает отсутствие заданного звука.
Метаданные не создают аудиосессию, не читают файлы и не меняют мир.

Когда появятся ресурсы, их разрешение и воспроизведение должны принадлежать общему
платформенному сервису, подключённому через DI. Экран передаёт ему описание
активной сцены и состояние жизненного цикла. Не создаём отдельный плеер и проверки
event ID в каждой карточке. Уход в фон останавливает воспроизведение; рекомпозиция
не должна начинать одну и ту же реплику заново. Правила повторения реплик, перехода
музыки и пользовательские настройки согласуются при реализации аудио.
Воспроизведение никогда не запускает повторно игровой выбор или его награду.

## Совместимость и проверка

Исторические определения остаются неизменяемыми. Изменение правил уже выпущенного
события оформляется новой версией ID с явными replacements/completion aliases,
как у очистки пластины. Эти таблицы служат совместимости; они не заменяют описание
нового события. Старые адаптеры копии для ещё не перенесённого контента допустимы,
но новые варианты не должны разносить свои правила по дополнительным проходам.

Новое поле `EventCardCopy.presentation` исключено из gameplay fingerprint:
смена иллюстрации, актуальной подписи или будущего аудио не ломает пересчёт истории.
Остальные прежние поля сохраняют правила fingerprint. Метаданные не добавляют
таблиц Room и не меняют формат снимка мира.

Для нового события проверяем уникальные стабильные ID, порядок вариантов,
денежные и предметные эффекты, расход сил, факты и итоговую фразу. Для изменения
авторского формата сравниваем скомпилированные данные прежней версии. Для макета
покупки нужна проверка отсутствующей иллюстрации. Поведение проверяется через
движок и repository; UI только показывает результат. Текущий режим проверки
проекта — сборка и компиляция тестовых исходников без запуска тестов/приложения.
