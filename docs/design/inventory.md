# Инвентарь

Обновлено: 2026-09-26. Основание: **MAIN-D-075**, **BALANCE-D-002** и
**FINANCE-UI-D-021 · Принято пользователем · 2026-09-26** в
[реестре решений](decisions.md). «Снаряжение» открывает приобретённые вещи,
а ниже — аксессуары. Группировки по главам нет: покупки прежних глав остаются
доступными вместе с новыми.

## Отображение

- Только экземпляры из сохранённого `GameState.ownedItems`. Каталог сам по себе
  не означает владение, выбранный образ питомца не создаёт вещь в инвентаре.
- Купленная вещь открывает полноэкранное иллюстрированное описание. Для карты
  звёзд пользователь запросил страницы с Орионом, Большой Медведицей и Млечным
  Путём; для телескопа — характеристики, для штатива — инструкцию.
- Название и описание предмета берутся из установленного каталога. Тематические
  страницы дополняют представление по точному `itemId`, не переписывают старое
  определение и не требуют повторной покупки. Неизвестный предмет сохраняет
  своё реальное описание, без подмены другим предметом или выдуманной страницей.
- Конкретная сетка, фон, иллюстрации, тексты, перелистывание и увеличение
  изображений — решения реализации для оценки, а не отдельно утверждённый макет.
  Увеличенный шрифт и узкое окно должны сохранять доступ к тексту и действиям.
- Каталожная цена — справочная, а не доказательство фактической старой оплаты.
  Неизвестную цену не заменяем нулём или стоимостью из визуального примера.
- Пустой раздел объясняет, где появятся приобретённые вещи. Загрузка и ошибка
  с повтором отделены от пустого инвентаря.
- Порядок и повторные экземпляры сохраняются внутри каждого раздела.
  Категория — расположение карточки, а не ограничение использования вещи в событии.

Открытие предмета, перелистывание справочных страниц и возврат не меняют игру.
Купленные вещи остаются у игрока после выполнения цели и перехода главы;
они не сдаются, не расходуются и не исчезают из инвентаря. Это относится также
к уже купленным предметам существующего сохранения.

Купленный аксессуар можно надеть или снять явной командой. Покупка и выдача
остаются в игровых карточках, покупки частей цели — на экране цели.
`SetPetLook` проверяет владение и ожидаемый текущий образ, сохраняет выбранный
образ и не расходует шаг, деньги или силы. Надевание не выдаёт вторую вещь;
снятие не удаляет имеющуюся. Новая игра с пустым владением остаётся пустой.

Кепка из старого сохранения отображается в аксессуарах через явное соответствие
ID, без изменения установленного определения STORY. Каталог образов связывает
приобретённый предмет с существующим рисунком текущего возраста и окраса.
Подробности и актуальные цены предложений —
в [дополнении по повседневному контенту](requirements/everyday-balance-2026-09-24.md).

## Предметы и оформление

Исторический источник названий и ориентиров иллюстраций:
[Figma, 2603:2](https://www.figma.com/design/bAod1cKtTX9Q8omQ067q3q/?node-id=2603-2).
На доске есть карта, компас, свиток, фонарь, ключ, звёздный диск, карта сети,
шестерёнка, кольцо и телескоп. Макет не задаёт цены.

В runtime названия, описания, категории и цены берутся из установленного
каталога. Предметы не ограничены перечислением ID и могут дополняться (D-070).
Существующие рисунки повторно используются по [каталогу ресурсов](assets/catalog.md)
и [манифесту](assets/manifest.json). Все 23 покупаемые части целей используют
отдельные иллюстрации `collection_*`. Общая привязка `goalItemArtwork(itemId)`
даёт один и тот же рисунок на экране цели, в копилке и в инвентаре.
Поездки и перевозки изображены билетами. Подробные звёздные страницы используют
`collection_sky_*`; изображения глав не подменяют изображения вещей.

Запрос пользователя не фиксирует астрономические факты или численные
характеристики телескопа; их нельзя приписывать ТЗ без отдельного основания.
Проверяемые сведения должны иметь отдельный источник,
а условное устройство из игрового мира — явно условное описание. Эти страницы
не добавляют экипировочные бонусы, новый доход, цену или механический эффект.

В текущем каталоге 23 части пяти больших целей. Для каждой части рисунок
привязан по точному `itemId`, а обычная страница сохраняет её каталожное
описание. Подробные тематические страницы добавляются только по явному
соответствию, не выводятся из похожих иконок или названий.
Оплаченные поездки и перевозки тоже сохраняются
как приобретения; просмотр такой записи не запускает поездку повторно.

## Первый аксессуар — 2026-09-27

По уточнению пользователя первый выбранный в onboarding аксессуар хранится
в инвентаре постоянно. Завершение onboarding добавляет ровно один `OwnedItem`
для выбранной банданы или рюкзака; «Без аксессуара» не создаёт вещь.
Не выбранный стартовый вариант и закрытые магазинные аксессуары не выдаются.
Оригинальные прозрачные рисунки — `gear_blue_bandana` и `gear_explorer_backpack`.
Снять аксессуар означает выбрать PLAIN, без удаления вещи, расходов или шага;
его можно снова надеть. Цена для стартовой вещи не придумывается и не показывается.

Существующие игры согласуются после установки каталога через агрегатный
репозиторий. В одной write transaction читаются актуальный снимок и его
INITIALIZED checkpoint. Если начальная выбранная вещь отсутствует, она
добавляется после прежних экземпляров; прошлые покупки, повторения, деньги
и история сохраняются. Без начального checkpoint доказательством служит
только текущая надетая бандана или рюкзак. Если такого свидетельства нет,
произвольный аксессуар не выдаётся. Изменение записывается как TECHNICAL_UPDATE
с outbox без финансовых операций или учебных фактов; повтор ничего не добавляет.
Room-схема не меняется: используются существующие ITEM и OWNED_ITEM.

В карточках инвентаря «Рассмотреть» и «Надеть»/«Снять» — отдельные кнопки
на всю ширину. Общая карточка больше не дублирует их нажатия. Цена также
занимает всю ширину, иконка и подпись выровнены по центру; склонение
соответствует сумме («24 монеты», «1 монета», «5 монет»).

## Данные и проверка

`GearViewModel` через Hilt получает `GameRepository`, `StoryContentRepository`
и `GameSession` для команды смены образа.
Наблюдение за сохранением запускает чтение неизменяемых определений. UI получает
`GearLoadState` и callbacks; маршрут Navigation 3 сохраняет прежний ID `gear`.
Отсутствующая ссылка на определение вызывает ошибку загрузки, не скрытие вещи.
Ключ экземпляра `OwnedItem.id` и ключ определения `itemId` различаются:
первый сохраняет конкретное приобретение, второй выбирает описание и рисунок.
Каталог справочных страниц не должен разбирать `itemId` из ID операции покупки.

Проверка существующего движка 2026-09-26: `BuyGoalItem` добавляет один
`OwnedItem` после проверок цели, владения и оплаты из реальной копилки.
Завершение главы очищает выбор цели и подцели, но не список вещей.
Согласование кампании и переход на бюджет v20 также сохраняют владение.
В текущем bundled-контенте нет REMOVE, а общий обработчик предметного REMOVE
отклоняет команду целиком, пока не определена отдельная политика потери.
По FINANCE-UI-D-021 такая будущая политика не должна удалять купленные вещи.

Room v5 сохраняет `ItemDefinition.category` и `priceCoins` в `ITEM`; изменение
каталога под существующим ID запрещено прежним контрактом install.
Миграция `4→5` добавляет поля без изменения владения, баланса и истории.
Legacy-категория STORY — техническое значение совместимости, не определение
категории по названию. Legacy-цена null не приравнивается нулю.
Схема и НФБК: [описание](schema-normalization.md#room-v5-категория-и-цена-предмета--2026-09-19).

Добавлены проверки фильтрации по владению, повторов, явных категорий, изменения
владения, ошибок и повтора загрузки, UI и миграции с переоткрытием базы.
По настройке пользователя выполняются только сборки и компиляция тестов;
запуск приложения, эмулятора и тестов не выполняется.
