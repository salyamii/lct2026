# Генератор полных JSON-примеров

`GenerateBackendExamples.java` создаёт шесть файлов в [examples](../examples)
через текущие классы `:core:game`, Kotlin serialization, `WorldSnapshotCodec` и отдельную проекцию аналитики:
`world-snapshot.json`, `snapshot-upload.json`, `snapshot-upload-response.json`,
`snapshot-download-response.json`, `analytics-upload.json`,
`analytics-upload-response.json`.

Это отдельная JVM-утилита документации. Она не запускает приложение, тесты,
Room или сеть; не читает пользовательское сохранение и не добавляет зависимостей
в production. Все значения синтетические и воспроизводимые. UUID прохождения,
upload и batch взяты из соседних примеров контракта. Во внешних запросах
используется один синтетический deviceId `9f1c2d3e4a5b6078`, передаваемый в JSON.
После генерации утилита также проверяет восемь готовых запросов/ответов
регистрации, download/query/pull/ACK и родительской выдачи настоящими Kotlin
serializers. Это проверка документационных payload, без запуска тестового runner.

Мир содержит питомца Рыжика, первый день, 100 монет, подтверждённые статьи
35/20/20/25 и одну запись `INITIALIZED`. В нём нет решений или результатов
тренировки, поэтому аналитика честно содержит пустые факты и все 12 навыков
с нулевыми свидетельствами. Запись INITIALIZED участвует только в локальной фикстуре аналитики; cloud JSON
содержит текущий мир без журнала. Это пример транспортного мира, не демонстрация
завершённого игрового сценария или освоенных навыков.

Checksum вычисляет `WorldSnapshotCodec`; перед записью генератор
декодирует архив и обе транспортные оболочки, проверяя контрольную сумму,
равенство мира и неизменность строки `snapshotJson`. `world-snapshot.json`
сохраняется **без завершающего перевода строки**: его UTF-8 содержимое точно
совпадает со значением `snapshotJson` после разбора внешнего JSON.

`currentContentFingerprint` также рассчитан настоящим `GameCatalogFingerprint`,
но относится к минимальному синтетическому каталогу генератора, а не полному
каталогу Android. `rulesId` и числовые настройки соответствуют текущим правилам
приложения. Пустые ссылки на контент не притворяются реальными пройденными сценами.
Сервер хранит архив как непрозрачную строку и не пересобирает его из примера.

Готовые JSON находятся внутри передаваемого backend-пакета; для их использования
запуск генератора не требуется. **Перегенерация выполняется только из корня
полного Android-репозитория LCTApp**, а не из отдельно распакованного ZIP:
утилите нужны исходники, Gradle-конфигурация и собранный модуль `:core:game`.
Генератор обновлён для нового формата, но в правке от 2026-09-29 не запускался:
пользователь выполняет сборку самостоятельно. При самостоятельной перегенерации
после изменений моделей сначала собрать модуль:

```powershell
./gradlew.bat :core:game:jar
./docs/backend/tools/Generate-BackendExamples.ps1 -JdkDirectory $env:JAVA_HOME
```

Нужен JDK 17 или новее; `JAVA_HOME` должен указывать на него, либо можно передать
полный путь прямо в `-JdkDirectory`. Проверенный запуск использовал JDK 21.
Скрипт использует уже разрешённые jars из Gradle cache
и версии из `gradle/libs.versions.toml` в Android-репозитории.
Сначала учитывается `GRADLE_USER_HOME`, затем стандартный `.gradle` пользователя.
При другом расположении кеша передать `-GradleCacheDirectory`; Gradle параллельно
со сборкой проекта запускать не требуется. Выходные `.class` лежат только
в `core/game/build/backend-example-generator`.

`ValidateBackendExamples.py` проверяет 21 транспортный JSON по схемам Draft 2020-12,
все ссылки OpenAPI, точное совпадение строки архива и локальные Markdown-ссылки.
Требуются Python, PyYAML и jsonschema; приложение, Gradle и тестовый runner
не запускаются. После обновления всех документов параметр `--package` собирает
`lct-backend-contract-v1.zip` из текущих файлов и сверяет байты каждой записи:

```powershell
python -X utf8 ./docs/backend/tools/ValidateBackendExamples.py --package
```

В полном репозитории проверяются также ссылки на исходники и design-документы.
Перегенерация и эта проверка предназначены для репозитория; получателю ZIP
достаточно готовых JSON и схем, исходный Android-проект для интеграции не нужен.
