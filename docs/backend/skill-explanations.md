# Короткие объяснения финансовых навыков

Обновлено: 2026-10-19. Необязательное дополнение контракта аналитики v1.

Детское приложение формирует один блок с описанием навыка и примерами из
сохранённых наблюдений. Сервер возвращает этот же текст встроенному и отдельному
родительским приложениям. Клиенты не переписывают его каждый по своим правилам.

Объяснение показывает, **что отмечено в игровых действиях**, а не назначает
ребёнку уровень навыка. Статус и `policyVersion` по-прежнему рассчитывает сервер.
Новые пороги, статусы, версии `schemaVersion`/`evaluatorVersion`, поля игрового
сохранения и изменения Room не вводятся.

Формулировки от 2026-10-19 описывают конкретные удачные решения и трудности
простыми словами. При смешанных результатах используется «не всегда»; один
случай не объявляется привычкой. Подписи счётчиков встроенного отчёта также
заменены обычными словами: «Получилось», «Возникли трудности», «С подсказкой
или помощью». Названия всех 12 навыков одинаковы в обоих родительских клиентах.

## Источник текста

Единый источник — [SkillExplanation.kt](../../core/game/src/main/kotlin/ru/nksk/lctapp/domain/analytics/SkillExplanation.kt):
`SkillExplanations.explain(SkillProfile)` и `SkillExplanation.isSupported()`.
Вход — уже рассчитанные наблюдения `SkillEvaluator`, без новой интерпретации
игрового журнала или обращения к генеративной модели. Проверки поведения:
[SkillExplanationsTest.kt](../../core/game/src/test/kotlin/ru/nksk/lctapp/domain/analytics/SkillExplanationsTest.kt).

- `description` кратко описывает, чему учится ребёнок.
- `summary` описывает совокупность доступных наблюдений. Это не объяснение
  серверного порога `MASTERED` или `HAS_PROBLEM`.
- `evidence` содержит до двух разных эпизодов с дополнительными основаниями и
  исходными идентификаторами фактов. Текст, который лишь повторяет `summary`,
  опускается. При наличии успехов и трудностей выбирается
  по одному примеру каждого вида. Идентификатор эпизода используется для
  устойчивого выбора; примеры не называются последними по времени.
- Незавершённая ситуация и нехватка данных не выдаются за ошибку или успех.
  Помощь, показанный ответ и тренировочный разбор отмечаются в тексте.
  Отсутствие игровых подсказок не означает отсутствие помощи взрослого.
- Текст объясняет наблюдаемый выбор ребёнка, а не перечисляет операции и остатки.
  Суммы остаются в измерениях аналитики; родитель видит, что получилось или
  вызвало трудность. Один случай обозначается отдельно, повторяющаяся особенность
  требует нескольких подходящих наблюдений. Автоматическое списание из запаса
  не описывается как отдельное самостоятельное решение ребёнка.
- Если история однозначно связывает пример с событием, `evidence.text` содержит
  его название и игровой день. Общий
  [SkillExplanationContexts](../../core/game/src/main/kotlin/ru/nksk/lctapp/domain/history/SkillExplanationContexts.kt)
  строит эту связь для локального отчёта и отправки. Для запаса день берётся из
  записи расхода, а не из дня распределения бюджета. Неполная история или
  неоднозначные ссылки не дополняются догадками; «в этой ситуации» без названного
  события не используется. Название берётся из текущего каталога по сохранённому
  идентификатору, это не обещание буквальной старой подписи экрана.

Описания всех двенадцати навыков приведены ниже в точности из общего источника.
При изменении формулировок таблицу и примеры следует обновлять вместе с ним.

| Навык | `description` |
| --- | --- |
| FIN-01 | Учится определять, где денег больше, меньше или поровну. |
| FIN-02 | Учится заранее делить деньги между нужными покупками, желаниями и накоплениями. |
| FIN-03 | Учится оставлять деньги на необходимое, когда хочется что-нибудь купить. |
| FIN-04 | Учится тратить так, чтобы денег хватило до следующего дохода. |
| FIN-05 | Учится регулярно откладывать на цель и не тратить накопленное. |
| FIN-06 | Учится подождать с желанной покупкой ради того, что сейчас важнее. |
| FIN-07 | Учится оставлять запас денег на случай неожиданной траты. |
| FIN-08 | Учится заново распределять деньги, когда появляется неожиданный расход. |

## Поля и ограничения

В [AnalyticsContract.kt](../../core/game/src/main/kotlin/ru/nksk/lctapp/domain/backend/AnalyticsContract.kt)
добавлено необязательное `explanation: SkillExplanation? = null`:

- в `SkillEvidenceDto` запроса `POST /v1/profiles/analytics`;
- в `SkillAssessmentDto` ответа `POST /v1/profiles/skills/query`.

При отсутствии блока поле опускается. Оба поля помечены
`@EncodeDefault(EncodeDefault.Mode.NEVER)`, поэтому чтение старого сохранённого
запроса не добавляет в его JSON новый `null`. Старые клиенты, отправляющие только
наблюдения, остаются совместимыми.

| Поле `SkillExplanation` | Ограничение |
| --- | --- |
| `version` | Целое `1`; всегда присутствует в отправляемом блоке благодаря `@EncodeDefault(ALWAYS)` |
| `description` | Непустая строка, 1–400 символов |
| `summary` | Непустая строка, 1–600 символов |
| `evidence` | Массив из 0–2 элементов с разными `episodeId` |

| Поле `SkillExplanationEvidence` | Ограничение |
| --- | --- |
| `episodeId` | Непустая строка; соответствует наблюдению этого навыка |
| `sourceEventIds` | Непустой массив разных непустых строк |
| `text` | Непустая строка, 1–400 символов |

Строка из пробелов не считается непустой; NUL отклоняют и `isSupported()`, и сервер.
Для идентификаторов и количества
`sourceEventIds` не вводится отдельного короткого ограничения: длинный эпизод
может ссылаться на много реальных фактов. Общие ограничения размера HTTP-запроса
сохраняются.

При загрузке аналитики набор `sourceEventIds` каждого примера должен **полностью
совпадать** с набором исходных фактов соответствующего наблюдения того же навыка
и `episodeId`. Одной совпадающей ссылки недостаточно. Порядок идентификаторов
не влияет на сравнение; дубликаты в примере недопустимы. Сами наблюдения уже
связаны с `facts` и `gameRunId` существующими проверками аналитики.

## Выдача сервером и восстановленная история

Сервер сохраняет принятый блок как часть проекции. Он рассматривает только
последнюю принятую проекцию по `throughHistorySequence`, затем `revision`,
затем `historyStartSequence`. Блок возвращается без изменения текстов только
тогда, когда **весь набор наблюдений навыка** из этой проекции
совпадает с объединёнными наблюдениями, по которым выдаётся оценка. Совпадения
только двух выбранных примеров недостаточно: `summary` относится ко всем
наблюдениям навыка. Сравниваются эпизоды и все значения наблюдений, не только
статусы или счётчики. Повторные записи эпизода исключают присоединение текста;
наблюдения без исходных фактов не входят в серверный расчёт и это сравнение.

После восстановления мира локальная история может начинаться позже серверной.
Если сервер учитывает сохранённый префикс, которого нет в локальном блоке,
объяснение нельзя приписать всей оценке. В таком случае `explanation` опускается;
сам статус сохраняется. Пропущенная история не достраивается, текст не
дописывается от имени ребёнка. Отсутствие блока также не означает `NO_DATA`.
Если последняя проекция пришла без объяснения, сервер не подставляет его из
предыдущей редакции. Новый полный согласованный пакет может вернуть блок.

Текущая версия отдельного родительского приложения, как и встроенная часть,
читает блок из `POST /v1/profiles/skills/query`. Для совместимости сервер
также возвращает такой же вложенный блок в `skills[]` ответа
`GET /api/parents/{petId}` рядом с `id`, `title` и `status`. Этот метод
по-прежнему выбирает прохождение последнего принятого snapshot, а блок берёт
из сохранённой оценки этого прохождения. На одной и той же подтверждённой
границе наблюдений оба родительских интерфейса показывают одинаковые формулировки. Свежий локальный
разбор и более ранняя серверная оценка не должны выдаваться за один результат.
Неподдерживаемый блок ответа можно скрыть, сохранив валидный статус навыка.

## Отправка и повторы

Используется существующая отправка аналитики, в том числе `refreshSkills()`:
загрузка фактов и наблюдений, проверка ACK, затем запрос оценок. Отдельного
метода для объяснений и нового расписания нет.

Новый блок включается в следующий **новый** пакет аналитики после изменения
истории. Уже сохранённые ожидающие запросы повторяются с прежним `batchId`,
ключом идемпотентности и прежним телом. Их нельзя обогащать объяснением под
старым ключом. Установка обновления сама по себе не заставляет повторно
загружать уже синхронизированную неизменившуюся историю; немедленное появление
блока для такой истории не обещается.

| Проверка запроса | Ответ сервера |
| --- | --- |
| Неподдерживаемая `explanation.version` | `422 UNSUPPORTED_SCHEMA` |
| Неверная связь с наблюдением или неполный/чужой набор исходных фактов; дубликаты эпизодов/ссылок, строки только из пробелов или с NUL | `422 INVALID_ANALYTICS` |
| Неверные типы, отсутствующие обязательные поля, пустой массив ссылок или превышение размеров блока | `400 INVALID_REQUEST` |

ACK, дедупликация фактов и применение серверной политики остаются прежними.

## Причина серверного статуса — 2026-10-19

В ответе `POST /v1/profiles/skills/query` элемент навыка может содержать
`assessmentReason: String` (1–600 символов). Это независимое от `explanation`
необязательное поле: его формирует сервер в той же ветке `skills-mvp-v1`,
которая назначает `status`, по тому же набору завершённых подходящих эпизодов.
Причина хранится вместе с оценкой и относится к её `policyVersion` и
`basedOnHistorySequence`. Старым сохранённым оценкам она не достраивается.
Отсутствие/повреждение необязательного поля не скрывает валидный статус.
Legacy-ответ `GET /api/parents/{petId}` переносит ту же сохранённую причину.

Оба родительских интерфейса разделяют значение навыка, наблюдаемые действия
(`summary`/`evidence`) и причину статуса (`assessmentReason`). При локальном
fallback разбор явно помечен как наблюдения устройства; причина остаётся
серверной. Описание и цель обучения не выводятся дважды. Буквальные повторы
абзацев исключаются без объединения разных игровых событий. Общая методика
в `researchBasis` выводится непосредственно перед источниками.

Нижние материалы каталога `2026-10-19-v2` отредактированы для всех FIN-01–FIN-12;
FIN-01 относится к сравнению сумм, а сравнение вариантов с учётом времени и
усилий остаётся FIN-09. Источники обосновывают учебный подход, не игровой порог
«два успеха» и не перенос освоения за пределы игры.

## Числовые наблюдения в обоих клиентах — 2026-10-19

Основа экрана — родительский режим детского приложения: числовые наблюдения
сохраняются и дополняются описанием, примерами и серверной причиной статуса.
Элемент ответа skills/query дополнительно содержит необязательный объект
`observationCounts`: `observedEpisodes`, `completedEpisodes`, `supportedEpisodes`,
`difficultyEpisodes`, `neutralEpisodes`, `pendingEpisodes`, `incompleteEpisodes`,
`supportedWithoutGameHints`, `assistedEpisodes`. Все значения — неотрицательные
целые, рассчитанные сервером из того же объединённого набора наблюдений,
к которому относятся статус и `basedOnHistorySequence`.

Оба клиента показывают серверные числа. Детское приложение сохраняет отдельный
локальный набор для работы без сети: при отсутствии серверных счётчиков он
подписан «Наблюдения на этом устройстве» и не подменяет причину серверного
статуса. Отсутствующий или повреждённый необязательный блок не превращается
в нулевые значения и не скрывает валидную оценку. Явные нулевые серверные
счётчики не заменяются более свежими локальными.
